# 弹幕个性化语音播报设计

日期：2026-08-30  
状态：已完成对话评审，待用户复核书面规格

## 1. 背景与目标

本项目是基于 Python、pywebview 和 Vue 3 的哔哩哔哩桌面直播工具，已经能够接收普通弹幕、进场消息、关注、分享和礼物事件。本次改进在现有弹幕链路上增加本地个性化语音播报。

首个音色是经授权的日配版灰原哀角色声线。训练素材为日语，运行时主要合成中文弹幕。授权范围已经由用户确认涵盖：AI 模型训练、生成新的合成语音和公开直播播放。

核心目标：

- 合成声音由用户主观判断是否符合目标角色的音色、性格和自然度。
- 正常负载下，一条短弹幕在收到后 1 秒内开始播放；可接受的尾部范围为 2–3 秒。
- 本地 RTX 3060 Laptop 6 GB 不为播报工具预留超过 1 GB 显存，首选 CPU 推理并实现零 GPU 占用。
- 训练使用云端 RTX 5090 32 GB；训练完成后，直播期间不依赖云服务器。
- 直播工具提供通用的本地音色选择接口，模型不硬编码到应用中。
- 低负载时按顺序播报；高负载时自动放弃过期普通弹幕，保持直播实时性。

## 2. 已知运行环境

- 本地 CPU：Intel Core i7-12700H，支持 AVX2。
- 本地 GPU：RTX 3060 Laptop 6 GB。
- 当前 WSL 可见内存约 8 GB；Windows 主机总内存未能由受限环境直接读取。
- 训练 GPU：云端 RTX 5090 32 GB。
- 当前桌面应用窗口为 1000 × 720，前端弹幕页由 `DanmuPanel.vue` 提供，后端弹幕事件由 `DanmuService` 解析并经 `ApiService` 推送给前端。

## 3. 范围

### 3.1 本次包含

- 本地可插拔音色包注册、校验、选择和试听。
- GPT-SoVITS CPU 推理引擎适配。
- 日语授权语料的数据准备、训练和中文跨语言测试流程。
- 弹幕文本规范化、自适应实时队列、语音合成和音频播放。
- 普通弹幕、礼物、舰长和关注等事件的可配置播报。
- 播报状态、队列状态、音量、语速、过滤和输出设备设置。
- 自动化软件测试、本地性能测试和用户主观音色验收材料。

### 3.2 本次不包含

- 在线音色商店或自动下载第三方模型。
- 云端推理服务或直播期间对云服务器的依赖。
- 在开源仓库或默认安装包中分发授权角色模型。
- 由自动指标代替用户判断音色效果。
- 自动回复弹幕、语言模型生成回复或虚拟主播对话系统。

## 4. 技术路线与阶段门

### 4.1 第一阶段：高质量模型直接本地运行

在云端使用授权日语语料微调 GPT-SoVITS V2 Pro/ProPlus。优先评估 ProPlus；如果其本地内存或延迟不符合要求，再比较 V2 Pro。直播电脑使用 CPU 优化推理实现，GPU 不参与推理。

选择该路线的原因：

- GPT-SoVITS 支持以日语参考音频合成中文目标文本。
- 少样本微调和角色音色生态成熟，最有希望先满足音色质量目标。
- 官方提供流式 API 语义，可在生成第一段音频后立即播放。
- CPU 推理能够满足显存约束，是否满足延迟目标通过本机基准测试决定。

### 4.2 第二阶段：轻量学生模型

只有第一阶段未达到性能门槛时才触发第二阶段。使用授权真实素材和经人工确认的教师模型中文输出训练单说话人轻量模型，导出为 ONNX，并通过 CPU 运行时加载。

第二阶段不得通过降低用户的音色验收标准来掩盖性能问题。轻量模型必须重新进行音色主观验收、中文测试和性能测试。

### 4.3 阶段门

第一阶段必须同时满足：

- 用户确认音色、性格和自然度可以接受。
- 20 个中文字符以内的弹幕，预热后首包延迟中位数小于 1 秒，P95 小于 3 秒。
- GPU 显存小于 1 GB，CPU 模式目标为零占用。
- 与 OBS 同时运行时，连续播报两小时无崩溃、内存持续增长或队列失控。

只要任一性能门槛未满足，就进入轻量化评估；音色未通过则继续调整训练数据、检查点、参考音频和推理参数，不直接进入学生模型训练。

## 5. 系统架构

保留现有 Vue + Python/pywebview 架构，新增四个职责单一的后端单元。

### 5.1 VoicePackRegistry

职责：

- 扫描本地音色目录。
- 解析并校验音色包清单。
- 返回可供前端展示的音色列表和健康状态。
- 阻止缺少授权说明、关键文件、兼容引擎版本或正确校验值的音色包加载。

音色模型不得写入账号配置。账号配置只保存被选择的 `voice_id` 和播报偏好。

### 5.2 TtsEngine

定义统一的本地推理接口，至少包含：

- `start(voice_pack)`：启动、加载并预热模型。
- `synthesize(request)`：返回流式 PCM/WAV 音频块。
- `cancel(request_id)`：取消尚未完成的合成。
- `health()`：返回引擎状态、版本和资源信息。
- `stop()`：退出并释放内存。

第一版实现 GPT-SoVITS CPU 引擎。轻量 ONNX 引擎以后实现相同接口，前端和调度器不感知底层模型变化。

GPT-SoVITS 以独立本地旁车进程运行。旁车只监听 `127.0.0.1`，使用应用启动时生成的随机端口和会话令牌，避免其他本地进程无意调用。旁车依赖与主应用隔离，防止 PyTorch、模型版本和 PyInstaller 打包依赖污染现有直播工具。

### 5.3 SpeechScheduler

职责：

- 接收弹幕和直播互动事件。
- 规范化文本并执行屏蔽策略。
- 估算待播放时长。
- 在顺序播报和实时丢弃模式之间自动切换。
- 仅向引擎预取当前和下一条消息。

### 5.4 AudioPlayer

职责：

- 接收并顺序播放流式音频块。
- 支持停止、跳过当前、音量控制和输出设备选择。
- 在切换音色、关闭播报或引擎失败时立即清理旧音频。

### 5.5 数据流

```text
B站弹幕 WebSocket
  -> 现有 DanmuService
  -> ApiService 事件分发
  -> SpeechScheduler
  -> 文本规范化与队列决策
  -> TtsEngine
  -> AudioPlayer
```

前端仍接收原有 `onDanmuMessage` 事件用于显示。播报逻辑位于后端，不依赖用户当前是否停留在弹幕页面，也不会因 Vue 组件的 KeepAlive 生命周期而重复启动。

## 6. 音色包合同

建议目录结构：

```text
voices/<voice-id>/
├── manifest.json
├── model/
├── reference.wav
├── reference.txt
├── preview.wav
└── LICENSE.txt
```

`manifest.json` 至少包含：

```json
{
  "schema_version": 1,
  "voice_id": "haibara-jp-authorized-v1",
  "display_name": "授权角色音色",
  "engine": "gpt-sovits-cpu",
  "engine_api_version": 1,
  "model_version": "v2-pro-plus",
  "source_language": "ja",
  "supported_output_languages": ["zh"],
  "reference_audio": "reference.wav",
  "reference_text": "reference.txt",
  "preview_audio": "preview.wav",
  "usage": ["ai_training", "synthetic_speech", "public_livestream"],
  "license_file": "LICENSE.txt",
  "files": {}
}
```

最终安装包必须在应用依赖锁中固定实际验证过的引擎提交版本；音色清单通过 `engine_api_version` 声明兼容的本地接口版本。`files` 必须包含关键文件的 SHA-256。安装或刷新音色包时拒绝路径穿越、软链接逃逸、缺失授权文件和校验不一致。

应用仓库不包含该授权模型。首版只提供“刷新音色列表”和“打开音色目录”，不提供在线下载或模型市场。

## 7. 训练数据合同

### 7.1 原始归档

- 首选 WAV 或 FLAC。
- 保留原始 44.1 kHz 或 48 kHz 采样率。
- 优先 24-bit PCM；16-bit PCM 可接受。
- 不覆盖、不降采样、不做破坏性降噪。
- 有损 MP3/AAC 只作为无法获得无损版本时的备选，并单独标记来源质量。

### 7.2 训练工作副本

- 单声道 PCM WAV。
- 每段 3–10 秒，以 4–8 秒为主。
- 一段仅包含一个说话人和一个完整句子。
- 头尾保留约 100–300 ms 自然静音。
- 不得包含其他角色、背景音乐、明显环境声、强混响、爆音或削波。
- 建议响度约为 -20 ± 2 LUFS，峰值不高于 -1 dBFS。
- 降噪必须经过前后盲听，不接受水声、金属声或被削弱的气声。

### 7.3 标注

GPT-SoVITS `.list` 格式：

```text
vocal_path|speaker_name|language|text
```

本项目示例：

```text
clips/train/000001.wav|haibara_jp_authorized|ja|そんな顔をしないで。冗談よ。
```

日文台词必须与实际发音一致，保留合理标点。训练条目的语言为 `ja`；推理时参考语言为 `ja`，目标文本语言为 `zh`。

### 7.4 数据划分与情绪元数据

- 第一轮选择 60–120 分钟音质和录音条件最一致的素材。
- 至少保留 10–15 分钟完全不参与训练的测试素材。
- 按原始节目、录音批次或场景分割训练集和测试集，避免相邻句泄漏。
- 额外标记冷静、怀疑、温柔、忧郁、紧张和讽刺等语气，用于抽样、参考音频选择和主观验收。
- 记录素材来源、授权标识、原始哈希、处理历史和质量检查结果。

## 8. 训练与中文跨语言适配

第一轮只使用经过筛选的授权日语真实素材，先保证音色、年龄感和角色性格稳定。训练完成后，以固定中文测试集比较多个检查点、参考音频和推理参数。

中文测试集约 200 条，覆盖：

- 短弹幕和较长句子。
- 数字、日期、时间、金额和数量词。
- 中文人名、日文角色名和常见 B 站昵称。
- 英文缩写、品牌名和中英混排。
- 网络词、问句、感叹句及不同情绪。

如果需要增强中文，只使用用户人工确认没有明显发音、口音和音质问题的合成输出。合成数据与真实数据分开追踪，并限制其比例，防止模型放大自身缺陷。

## 9. 文本规范化与安全过滤

每条待播报消息依次执行：

1. 删除 URL、控制字符和不可读零宽字符。
2. 将连续标点压缩到合理长度。
3. 默认忽略表情；可将少量白名单表情转换成短词。
4. 对数字、日期和常用单位做中文可读化。
5. 应用用户黑名单、屏蔽词和正则过滤。
6. 合并同一用户在短时间内发送的碎片消息。
7. 在自然标点处将播报文本限制到约 50 个中文字符。

用户名默认不播报，用户可以开启。用户名开启后也必须经过相同规范化和长度限制。

## 10. 自适应实时队列

调度器根据当前音频剩余时长、已排队文本估算时长和近期合成速度计算预计等待时间。

- 预计等待不超过 2 秒：普通弹幕按 FIFO 顺序播报。
- 预计等待超过 2 秒：移除已经等待约 3 秒仍未开始合成的普通弹幕，只保留最新的可播报消息。
- 完全重复或短时间刷屏消息合并。
- 礼物、舰长、关注等事件可设为高优先级，并排到下一条；默认不打断正在播放的语音。
- 调度器只预生成当前和下一条，避免为即将过期的消息浪费 CPU。
- 关闭播报或切换音色时取消未完成合成并清空旧队列。

缓存仅保存少量规范化文本与音色参数完全相同的短句。缓存使用 LRU 上限，可由用户清除，且不得无限增长。

## 11. 前端体验

在弹幕页顶部增加紧凑工具栏：

- 语音播报开关。
- 当前音色下拉选择。
- 未启动、加载中、就绪、正在播报和故障状态。
- 当前队列数量和预计延迟。
- 跳过当前按钮。
- 设置入口。

音色项展示名称、封面、试听、来源语言、输出语言、引擎、模型版本和授权状态。

常用设置：

- 音量和语速。
- 是否读取用户名。
- 普通弹幕、礼物、舰长和关注等事件开关。
- 实时优先模式。

高级设置：

- 最大弹幕长度。
- 队列等待与过期阈值。
- 屏蔽词、用户黑名单和正则过滤。
- 音频输出设备。
- CPU 线程数。
- 缓存上限。

设置按账号保存到现有应用配置；模型和缓存不复制进账号记录。

## 12. 生命周期与错误处理

- 开启播报：校验音色包，启动旁车，加载并预热模型，健康检查通过后状态变为就绪。
- 单条合成失败：记录可读错误，跳过该条，不阻塞后续队列。
- 旁车崩溃：自动重启一次；再次失败后关闭播报并向用户显示原因。
- 音频设备不可用：停止播放，保留界面可操作性，提示重新选择设备。
- 切换音色：停止当前音频，清空未播放音频，加载新音色并重新预热。
- 关闭播报：取消合成、停止播放、清空队列、退出旁车并释放模型内存。
- 退出应用或切换账号：调度器停止接收新消息；音色选择可按账号恢复，但模型进程不得重复启动。

日志不得包含完整授权音频、模型二进制或未经必要脱敏的用户标识。旁车错误需要映射为简短用户提示，同时将技术详情写入本地日志。

## 13. 测试与验收

### 13.1 用户音色验收

音色效果由用户最终判断，不设置第三方评分或自动相似度通过线。每轮训练提供匿名 A/B 材料：

- 相同中文测试句在不同检查点和推理参数下的输出。
- 冷静、怀疑、温柔、紧张等代表性语气。
- 数字、人名、英文缩写和网络词。
- 对应噪声、延迟和资源报告。

用户按“更像角色、自然度更好、中文更顺”选择。自动指标只发现静音、爆音、重复、吞字、明显发音错误和音频损坏，不替用户决定音色优劣。

### 13.2 本地性能验收

在 i7-12700H 上与 OBS 同时运行：

- 20 个中文字符以内的弹幕，预热后首包延迟中位数小于 1 秒，P95 小于 3 秒。
- GPU 显存小于 1 GB，CPU 模式目标为零。
- 连续两小时播报无崩溃和持续内存增长。
- 高峰模拟后队列可以回到 FIFO 正常状态。
- 关闭播报后模型进程退出，模型占用的内存得到释放。

### 13.3 软件自动化测试

- 单元测试：音色包校验、文本清洗、数字规范化、重复合并、优先级、等待估算和过期策略。
- 集成测试：使用假 TTS 引擎验证启动、流式返回、取消、崩溃恢复和音频播放器调用，不要求 CI 加载真实模型。
- 前端测试：播报开关、音色切换、状态显示、错误提示和设置持久化。
- 端到端测试：使用真实授权音色包进行本地直播模拟。

## 15. 完成定义

本设计的实现完成需要满足：

1. 用户能够安装、刷新、试听和选择合法音色包。
2. 授权日语角色模型能够在本地离线合成中文弹幕。
3. 播报队列符合低负载顺序、高负载实时丢弃的约定。
4. 资源、延迟和稳定性通过第 13 节的性能验收。
5. 用户主观确认最终音色效果。
6. 自动化测试覆盖核心边界和错误路径。
7. 应用仓库和默认安装包不包含授权角色模型。
